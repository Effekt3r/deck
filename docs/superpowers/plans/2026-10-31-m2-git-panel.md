# Deck M2 — Git panel Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A git panel on the left of every terminal tab that is in a git repo: a header (branch, merge target, commits to merge, upstream, work-tree state, merge/rebase in progress) and a Sourcetree-style commit graph of all branches that redraws live as Claude commits, merges and tags. Milestone M2 in `docs/DECK.md`.

**Architecture:** The main process owns git: one runner (`GIT_OPTIONAL_LOCKS=0`, no fsmonitor, timeouts), the summary/log/details readers ported from `git_graph_pane.py`, merge-target rules, a per-repo watcher (fs.watch on the git dir, debounced, plus a poll) and `git:*` IPC with push updates. The renderer computes graph lanes (pure, tested) and draws them on one canvas behind a virtualised list of DOM rows.

**Tech Stack:** as M1 (Electron 45, React 19, TypeScript 7, vitest 5, Node 22); git CLI.

## Ground rules

Everything in the M1 plan's ground rules applies (`docs/superpowers/plans/2026-10-30-m1-electron-shell.md`): macOS **and** Windows 11, sandboxed renderer, Node 22 (`export PATH="$HOME/.nvm/versions/node/v22.19.0/bin:$PATH"`), implementer subagents don't commit, branch `m2-git-panel`. Also read `CLAUDE.md` ("How the prototype fits together" for the merge-target rules; "Current state" for M1's non-obvious parts).

- **Read-only towards the repo.** Deck never runs a git command that writes (no `fetch`, no `config --set`, no `gc`). The merge-target override chosen in the UI is stored in Deck's userData, not in `.git/config`. Every git call sets `GIT_OPTIONAL_LOCKS=0`, `GIT_TERMINAL_PROMPT=0` and `-c core.fsmonitor=false`.
- Flow control rule from M1 is untouched (this milestone doesn't write to xterm).

**Behaviour details:**
- `readSummary`: branch via `symbolic-ref --short -q HEAD`; head via `rev-parse --short HEAD` (empty repo → `''`); operation from files in `gitDir` (`MERGE_HEAD`, `rebase-merge`, `rebase-apply`, `CHERRY_PICK_HEAD`, `REVERT_HEAD`); upstream via `rev-parse --abbrev-ref --symbolic-full-name @{u}` and `rev-list --left-right --count HEAD...@{u}`; target via `mergeTarget` + `rev-list --count target..HEAD` / `HEAD..target`; counts from `status --porcelain=v1` (`countStatus` rules from `git_graph_pane.py`).
- `readLog`: `log --all --exclude=refs/stash --date-order --skip=<skip> --max-count=<limit> --format=%H%x1f%P%x1f%D%x1f%s%x1f%ct%x1f%an%x1e`; empty repo → `[]`. `parseRefs`: `HEAD -> main` → `{ name: 'main', kind: 'branch', current: true }`; bare `HEAD` → `{ name: 'HEAD', kind: 'head' }`; `tag: v1` → tag; names under any remote (`origin/x`, `upstream/x`; know remotes from `git remote`) → remote; `*/HEAD` dropped.
- `readDetails`: `show -s --format=%H%x1f%P%x1f%an%x1f%ae%x1f%ct%x1f%B <hash>`; files via `diff-tree -r -M --root --no-commit-id --name-status` and `--numstat` against the first parent (`<hash>^1 <hash>` for merges, `--root <hash>` otherwise); unknown hash → null.
- `ipc.ts`: subscriptions keyed by `webContents.id` + repo root (the repo argument may be any folder inside the repo: resolve with `gitDirs`). One watcher per repo root, ref-counted; on change rebuild the snapshot (`readSummary`, `readLog(0, LOG_PAGE)`, `readToMerge`) and `send(IPC.gitUpdate, repoArg, snapshot)` to each subscriber, skipping identical snapshots (compare JSON). Drop a webContents' subscriptions on `destroyed`. `setTarget` stores the override, then refreshes that repo. Validate every argument type; handlers never throw for bad input (resolve null/[] instead).

### Task 3: Graph lanes (Agent B)

**Files:** `src/renderer/src/git/lanes.ts`, `lanes.test.ts`.

```ts
export interface Segment { from: number; to: number; color: number }
export interface GraphRow {
  /** Lane of this commit's dot. */
  lane: number
  /** Colour index of the dot (its lane's chain). */
  color: number
  /** Upper half: lane `from` at the row's top edge → lane `to` at its middle. */
  up: Segment[]
  /** Lower half: lane `from` at the middle → lane `to` at the bottom edge. */
  down: Segment[]
  /** Lanes the row spans (highest occupied lane + 1, before or after the commit). */
  width: number
}
export function layoutGraph(commits: { hash: string; parents: string[] }[]): GraphRow[]
```

**Algorithm** (one pass, newest first): `lanes` holds, per lane, the commit it expects next and that lane's colour.
1. The commit's lane is the first lane expecting it; if none, it's a branch tip: put it in the first free lane (or a new one) with a new colour.
2. `up`: for every occupied lane `i` (as it was when the row was reached, tip included): if it expects this commit, segment `i → lane` (a tip draws none); otherwise pass-through `i → i`.
3. Lanes other than `lane` that expected this commit become free.
4. `lanes[lane]` = first parent with the same colour (none for a root commit → free). Each further parent: if some lane already expects it, that lane is a merge target; otherwise it goes in the first free lane with a new colour and is a merge target.
5. `down`: for every occupied lane `i` afterwards: `i === lane` → `lane → lane`; a merge target → curve `lane → i`, plus `i → i` if that lane was already occupied before step 4; otherwise pass-through `i → i`.

```ts
import { describe, expect, it } from 'vitest'
import { layoutGraph, type Segment } from './lanes'

const c = (hash: string, ...parents: string[]) => ({ hash, parents })
const seg = (s: Segment[]) => s.map((x) => `${x.from}>${x.to}`).sort()
const view = (commits: ReturnType<typeof c>[]) =>
  layoutGraph(commits).map((r) => ({ lane: r.lane, up: seg(r.up), down: seg(r.down) }))

describe('layoutGraph', () => {
  it('linear history stays in lane 0', () => {
    expect(view([c('c3', 'c2'), c('c2', 'c1'), c('c1')])).toEqual([
      { lane: 0, up: [], down: ['0>0'] },
      { lane: 0, up: ['0>0'], down: ['0>0'] },
      { lane: 0, up: ['0>0'], down: [] },
    ])
  })
  it('a merge forks a lane and the branches join again at their base', () => {
    expect(view([c('M', 'A', 'B'), c('B', 'C'), c('A', 'C'), c('C')])).toEqual([
      { lane: 0, up: [], down: ['0>0', '0>1'] },
      { lane: 1, up: ['0>0', '1>1'], down: ['0>0', '1>1'] },
      { lane: 0, up: ['0>0', '1>1'], down: ['0>0', '1>1'] },
      { lane: 0, up: ['0>0', '1>0'], down: [] },
    ])
  })
  it('an unmerged branch tip gets its own lane', () => {
    expect(view([c('F2', 'F1'), c('M2', 'M1'), c('F1', 'M1'), c('M1')])).toEqual([
      { lane: 0, up: [], down: ['0>0'] },
      { lane: 1, up: ['0>0'], down: ['0>0', '1>1'] },
      { lane: 0, up: ['0>0', '1>1'], down: ['0>0', '1>1'] },
      { lane: 0, up: ['0>0', '1>0'], down: [] },
    ])
  })
  it('a freed lane is reused by the next tip, with a new colour', () => {
    const rows = layoutGraph([c('A', 'B'), c('X', 'Y'), c('B'), c('Z'), c('Y')])
    expect(rows.map((r) => r.lane)).toEqual([0, 1, 0, 0, 1])
    expect(rows.map((r) => r.color)).toEqual([0, 1, 0, 2, 1])
    expect(seg(rows[2].down)).toEqual(['1>1'])
    expect(seg(rows[3].up)).toEqual(['1>1'])
  })
  it('an octopus merge fans out to every parent', () => {
    expect(view([c('M', 'A', 'B', 'C'), c('A'), c('B'), c('C')]).map((r) => [r.lane, r.down])).toEqual([
      [0, ['0>0', '0>1', '0>2']], [0, ['1>1', '2>2']], [1, ['2>2']], [2, []],
    ])
  })
  it('a merge parent already in another lane gets a curve into that lane', () => {
    expect(view([c('Y', 'B'), c('X', 'A', 'B'), c('A', 'B'), c('B')])).toEqual([
      { lane: 0, up: [], down: ['0>0'] },
      { lane: 1, up: ['0>0'], down: ['0>0', '1>0', '1>1'] },
      { lane: 1, up: ['0>0', '1>1'], down: ['0>0', '1>1'] },
      { lane: 0, up: ['0>0', '1>0'], down: [] },
    ])
  })
  it('reports how many lanes each row spans', () => {
    expect(layoutGraph([c('M', 'A', 'B'), c('B', 'C'), c('A', 'C'), c('C')]).map((r) => r.width)).toEqual([2, 2, 2, 2])
  })
  it('lays out 10,000 commits quickly', () => {
    const commits = Array.from({ length: 10_000 }, (_, i) =>
      c(`h${i}`, ...(i + 1 < 10_000 ? [`h${i + 1}`] : []), ...(i % 50 === 0 && i + 25 < 10_000 ? [`h${i + 25}`] : [])))
    const t = performance.now()
    expect(layoutGraph(commits)).toHaveLength(10_000)
    expect(performance.now() - t).toBeLessThan(500)
  })
})
```

### Task 4: Graph view (Agent B)

**Files:** `src/renderer/src/git/GraphView.tsx`, `graph.css`.

```ts
interface GraphViewProps {
  commits: GitCommit[]
  rows: GraphRow[]                 // layoutGraph(commits), memoised by the caller
  toMerge: ReadonlySet<string>
  selected: string | null
  onSelect(hash: string): void
  hasMore: boolean
  onNeedMore(): void               // near the end of the list and hasMore
}
```

- Fixed row height 24 px, lane width 14 px, dot radius 4 (HEAD's commit: ring). One `<canvas>` covering the visible viewport, redrawn on scroll/resize/data change for the visible rows only, scaled by `devicePixelRatio`. Per row at `y`: `up` segments from `(x(from), y)` to `(x(to), y + 12)`, `down` from `(x(from), y + 12)` to `(x(to), y + 24)`; equal lanes are straight lines, different lanes a cubic Bézier with vertical tangents (Sourcetree-like). Lane colours: 8-colour palette starting teal `#3DDCC1`, amber `#FF9F43`, violet `#A78BFA`, blue `#7AA2F7`, pink `#F7768E`, green `#9ECE6A`, orange `#E0AF68`, cyan `#7DCFFF`.
- Rows: absolutely positioned DOM rows for the visible range ± 20, text starting after the graph gutter (`max visible width × 14 + 8` px): short hash (7) — amber filled badge when in `toMerge` —, ref pills (current branch: teal filled; branch: teal outline; remote: dim outline; tag: amber outline; HEAD detached: violet), subject (bold when in `toMerge`), and right-aligned age (`ago()` from `projects/filter.ts`) and author's first name. Selected row highlighted; click → `onSelect`. Long subjects ellipsised. Keyboard: ↑/↓ moves the selection, Enter opens it (`onSelect`).
- Call `onNeedMore` when the last rendered row is within 50 of the end and `hasMore` (once per length).
